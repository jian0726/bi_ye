## 19:00-20:00 refresh token 机制落地（用户指令：把审计里指出的死代码补全）

**背景**：审计 P1「JWT 无撤销、无 refresh」，`request.ts` 里清理 `refresh_token` 是死代码——机制设计过但从未实现，token 签发后 72h 不可撤销。

**方案（用户选「完整方案」）**：双 token 轮换制，access 2h / refresh 7d。

**后端**：
- `application.yml`：`jwt.expire-hours: 72` → `jwt.access-hours: 2` + `jwt.refresh-days: 7`
- `util/JwtUtil`（重写）：`issueAccess(userId, role)` / `issueRefresh(userId, jti)`；
  两个 token 都带 `claim("type", "access"|"refresh")` 防混用；`parseAccess` / `parseRefresh` 各校验 type
- `service/TokenService`（新建）：Redis key `blog:auth:refresh:{jti}` → userId，TTL 7 天；
  `register` / `isRegistered` / `revoke`（**删除即撤销**，与既有 `blog:verify:*` 同风格）
- `service/UserService`：`buildVO` 生成 `jti=UUID` 并 `register`；
  `refresh(refreshToken)` = parseRefresh → isRegistered → 回库查用户（注销/禁用则 revoke + 401/403）
  → **revoke 旧 jti → 发新对**（轮换）；`logout(refreshToken)` = revoke
- `interceptor/AuthInterceptor`：`parse()` → `parseAccess()`，**refresh 不能当请求凭证**
- `controller/AuthController`：新增 `POST /auth/refresh`、`POST /auth/logout`（body 可选）
- 新增 DTO：`RefreshTokenDTO`（@NotBlank）、`LogoutDTO`
- `vo/LoginVO`：加 `refreshToken`

**前端**：
- `api/request.ts`（重写）：401 拦截 → `AUTH_FREE_URLS` 白名单（refresh/login/register/logout）
  → `tryRefresh()` 裸 axios 打 `/api/auth/refresh`，模块级 Promise **单飞**防并发重复刷新
  → 成功重放原请求（`_retried` 标志防循环），失败 `redirectToLogin()`
- `api/auth.ts`：`LoginResult` 加 `refreshToken`；新增 `refreshAuth()` / `logoutApi()`
- `stores/user.ts`：`logout()` 先 fire-and-forget 调 `logoutApi(refreshToken)` 再清本地
- `LoginView.vue` / `RegisterView.vue`：`setTokens(res.token, res.refreshToken)`

**验证**：`mvn compile` ✓、`vue-tsc` ✓。**冒烟未跑完**（见下）。

**备份**：`scripts/backup/refresh-token-before/`（8 个文件）。

### ⚠ 排障记录：后端启动报 62969 端口占用（重要，勿再踩）

现象：`java -jar target/blog-backend.jar` 报 `Tomcat initialized with port 62969` +
`Port 62969 was already in use`，但 **jar 内 `application.yml` 确认为 `server.port: 8080`**，
外部无 `config/application.yml`，`SERVER_PORT` 环境变量为空。

**根因**：**沙箱运行时向子进程注入了随机端口的 `SERVER_PORT`**（Spring 的 relaxed binding
使环境变量优先级高于 jar 内 yml），并非代码或配置问题。

**解法**：命令行参数优先级最高，显式覆盖即可：
```
/d/Java21/bin/java.exe -Dfile.encoding=UTF-8 -jar target/blog-backend.jar --server.port=8080
```
覆盖后正常启动（`Started BlogApplication in 4.918 seconds`）。

**另注**：JDK 必须用 `D:\Java21\bin\java.exe`（默认 `java` 是 8，class 52，报 UnsupportedClassVersionError）。
