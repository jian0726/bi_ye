### ⚠⚠ 踩坑：`--force-recreate` 会连带重建依赖容器 + 丢环境变量

第一次执行 `docker compose up -d --force-recreate frontend`（**只写了 frontend，没带 BACKEND_PORT**）：
- compose 把 **backend 也 recreate 了**（frontend depends_on backend）
- 且**`--force-recreate` 没继承上次的环境变量** → `BACKEND_PORT` 回退默认 **8080**
- 而 8080 被其他项目 Jenkins 占用 → 端口映射错误，后端直连 502
- **更严重**：recreate 后 backend 用的是**镜像内的旧 jar**（10-05 22:23），
  之前 `docker cp` 进去的新 jar 被覆盖 → `/api/auth/refresh` 直接 **404 接口不存在**
- **解法**：`BACKEND_PORT=8081 FRONTEND_PORT=5174 docker compose up -d --force-recreate backend`
  ——**每次 recreate 都必须把端口环境变量写全，不能省略**
- **规律 R25**：`--force-recreate` 不继承环境变量；只要用过端口覆盖，之后每条 compose 命令都要重复写
- **规律 R26**：判断容器内 jar 是否为最新，看 mtime + 字节数，**不要相信「我刚 build 过」**；
  `docker cp` 改过的容器一旦被 recreate 即回退到镜像内容

- 第一版我把 `APP_TRUSTED_PROXIES` 写成 `127.0.0.1,::1,172.20.0.0/16`（**整个 Docker 网段**）。
  实测负向测试失败：**从宿主机直连 8081 发 `X-Forwarded-For: 8.8.8.8` 被采信并写库**。
  原因：宿主机经 Docker 端口转发进来的请求，`remoteAddr` = **网关 172.20.0.1**，它落在 /16 网段内。
  → **写网段等于对宿主机开放 XFF 伪造**。
- **正解**：只白名单**前端容器那一个固定 IP**。为此新建自定义网络 `jianyou-net`（subnet 172.28.0.0/24），
  给**每个服务都钉死固定 IP**（backend .2 / frontend .3 / mysql .11 / redis .12 / minio .13），
  白名单写 `127.0.0.1,::1,172.28.0.3`。固定 IP 而非网段——因为 nginx 是唯一反代。
- 修后复验：正测（经 nginx 172.28.0.3 带 XFF 220.181.38.148）→ 落库 `220.181.38.148`（北京）✅；
  负测（直连 8081 带 XFF 8.8.8.8）→ 落库 `172.28.0.1`（真实网关），伪造失败 ✅。
- **规律 R27**：Docker 里做 XFF 白名单**绝不能写网段**（网关必在内），要么钉固定 IP，要么用 host 网络。
- **规律 R28**：`IpUtils` 已支持 CIDR 写法（`172.28.0.0/24`），但生产实际只用精确 IP；CIDR 能力保留备用
  （真生产若在反代后加二层代理才需要）。
