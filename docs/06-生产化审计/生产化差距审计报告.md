## 二、P0 高危（上线即事故）

### P0-1 Redis 暴露宿主机且无密码 → 可接管任意账号
- 证据：`docker-compose.yml:44-45`（`6380:6379` 映射）、无 `requirepass` 配置；`application.yml:26-29`（Redis 未配置 password）。
- 影响：验证码明文存于 `blog:verify:*`。任何能访问宿主机 6380 端口的人可 `GET` 出验证码，走 `/auth/reset-password` **重置任意账号（含站长）密码**。
- 建议：Redis 加 `--requirepass`；端口映射改为 `127.0.0.1:6380:6379` 或干脆删除 `ports`（容器网络内互通即可）。

### P0-2 MySQL root 与 MinIO 控制台对外暴露
- 证据：`docker-compose.yml:19`（`MYSQL_ROOT_PASSWORD: root2026`）、`:30`（`3307:3306`）、`:55`（`minioadmin2026`）、`:60`（`9001:9001` 控制台）。
- 影响：root 直连数据库；MinIO 控制台弱口令可登，全量对象可读写。
- 建议：MySQL/MinIO 端口仅绑 `127.0.0.1`；root 强密码；控制台不对外。

### P0-3 全部密钥明文进仓库
- 证据：`docker-compose.yml:19,22,54-55,71`；`application.yml:21,43,50,59-60`（`jianyou2026` / JWT 默认串 / `VERIFY_DEV_MODE:true` 兜底 / `minioadmin2026`）；`DataLoader.java:28`（站长初始密码 `jianyou2026`，与 MySQL 密码同串）。
- 影响：仓库一旦外传（毕设要提交源码！），攻击链全通：登录站长 → 后台 → 数据库。
- 建议：仓库只留 `.env.example`；真实值放 `.env`（compose 已支持变量替换）或部署机环境变量；站长首次登录强制改密；`VERIFY_DEV_MODE` 上线必须 `false`（`application.yml:49-50` 的 TODO 自己也标注了）。

### P0-4 无版本控制
- 证据：项目根、blog-backend、blog-web 均无 `.git`。
- 影响：不可回滚、无变更审计、多人协作必乱；毕设交付也无法证明代码演进。
- 建议：立即 `git init` + 首次提交；`.gitignore` 已有（blog-web/.gitignore），补后端一份。

### P0-5 Docker 部署下 >1MB 上传全部失败（功能性事故）
- 证据：`blog-web/nginx.conf` 全文无 `client_max_body_size`（nginx 默认 **1m**）；上传走 `location /api/` 反代（nginx.conf:15-21）；而后端允许图片 5MB / 音频 1028MB（`StorageService.java:47-49`）。
- 影响：容器化部署后，2MB 头像、5MB 图片、1GB 音频上传一律被 nginx 413 拦截。开发模式（vite 代理）无此限制，所以本地测不出来。
- 建议：`location /api/` 内加 `client_max_body_size 1100m;`，并同步 `proxy_read_timeout`（当前 30s，nginx.conf:20，大文件场景偏紧）。

### P0-6 验证码开发模式回传明文
- 证据：`application.yml:50`（`dev-mode` 默认 `true`）、`AuthController.java:114-119`（响应体带 `devCode`）、`ConsoleCodeSender.java`（验证码打控制台）。
- 影响：上线若忘关，找回密码接口直接把验证码还给调用方，等同无验证码。
- 建议：默认值反转（生产必须显式开 dev-mode 才回传）；启动时检测 `dev-mode=true && 非本地 profile` 则告警日志。

## 三、P1 中危（生产前必须补齐）

### P1-1 会话生命周期不完整 —— ✅ 已于 2026-10-07 整改

- ~~无登出撤销：token 签发后 72h 内始终有效（`application.yml:44`、`JwtUtil.java:36`），无黑名单、无 refresh token。`request.ts:42` 清理的 `refresh_token` 是不存在的死代码。~~
- **整改结果**：已实现双 Token 体系——access 2h（`jwt.access-hours`）+ refresh 7d（`jwt.refresh-days`）；
  refresh 的 `jti` 登记 Redis `blog:auth:refresh:{jti}`（TTL 7 天，**删除即撤销**）；
  `POST /auth/refresh` 为轮换制（撤销旧 jti 再发新对）；`POST /auth/logout` 撤销；
  拦截器改为只认 access（`parseAccess` 校验 `type=access`，refresh 不能当请求凭证）；
  前端 `request.ts` 401 单飞刷新 + 重放原请求，原「死代码」已变为真实链路。
  涉及 `JwtUtil`（重写）、`TokenService`（新增）、`UserService`、`AuthInterceptor`、`AuthController`、
  `request.ts`（重写）、`auth.ts`、`stores/user.ts`、`LoginView` / `RegisterView`。
- **role 写死在 token 内的问题同步解决**：refresh 时**回库读取最新 `role` / `status`**，降权与禁用立即生效（原最长 72h 延迟）。
- **遗留（可接受）**：未做 access 黑名单——access 到期前仍有效（最长 2h），靠短效期收敛风险；
  与「Redis 只承担天然带有效期的数据」原则一致，建议写入论文"不足与展望"。

### P1-2 登录无失败锁定、写接口无限流
- 证据：`UserService.java:68`（login 无失败计数）；全后端无任何 RateLimit 实现（grep 零命中）；留言板无频率限制（`MessageService`，未落地清单原有项）；`/portal/music/uploads` 登录用户即可上传 1GB 音频（`MusicController.java:22,34`、`MusicService.java:69` 仅要求登录）。
- 建议：登录失败 5 次锁 15 分钟（Redis 计数即可）；留言/上传按 IP+用户做简单滑动窗口限流。

### P1-3 无 HTTPS 与安全响应头
- 证据：`nginx.conf:2` 仅 `listen 80`；无 CSP / X-Frame-Options / X-Content-Type-Options / HSTS。
- 建议：上线前套 TLS（宝箱域名 + certbot 或云负载均衡）；nginx 统一加安全头。

### P1-4 CORS 全放开且无环境区分
- 证据：`WebConfig.java:24` `allowedOriginPatterns("*")`，注释写"生产走 nginx 同源反代"，但**没有 profile 开关**，生产照样生效。
- 建议：`application-prod.yml` 收敛为具体域名；同时补 dev/prod profile 分离（当前全项目只有一份 `application.yml`）。

### P1-5 可观测性缺位
- 无 Actuator（`pom.xml` 依赖清单无）；无健康检查：compose 里 backend/redis/minio 无 healthcheck（`docker-compose.yml:39-46,49-61,63-87`）；日志仅 `logging.level` 一行（`application.yml:65-67`），无 logback 滚动文件、无 traceId；docker 默认 json-file 日志**无上限**，长期运行撑爆磁盘。
- 建议：加 `spring-boot-starter-actuator`（暴露 health/info）；compose 补 healthcheck 与 `logging: options: max-size: 50m, max-file: 5`；logback-spring.xml 按天滚动 + 保留 14 天。

### P1-6 容器无资源上限、JVM 无内存约束
- 证据：`blog-backend/Dockerfile:22`（裸 `java -jar`，无 `-XX:MaxRAMPercentage`）；compose 全部服务无 `mem_limit/cpus`。
- 影响：流量尖峰时 JVM 吃满宿主机内存，连带 MySQL 被 OOM-kill。
- 建议：`ENTRYPOINT` 加 `-XX:MaxRAMPercentage=75 -XX:+UseG1GC`；compose 加 `deploy.resources.limits` 或 `mem_limit: 512m`。

### P1-7 零备份
- 证据：无任何 mysqldump/快照脚本（`scripts/` 下 `backup*` 是文档备份脚本，非数据库备份）；无 binlog 配置。
- 建议：`mysqldump --single-transaction` 每日 cron + 保留 7 天；MinIO 数据卷同策略。

### P1-8 数据库迁移无基线工具
- 证据：`db/` 下 ✅ **2026-10-07 已合并为单一 `init.sql`**（原 10 个手工 `upgrade-*.sql` 已删除，备份留在 `db/_backup-before-merge/`）；但 `init.sql` 仍只在空卷执行一次（`docker-compose.yml` 挂 `/docker-entrypoint-initdb.d/`），pom 无 Flyway/Liquibase。
- 影响：换机部署虽已不必人肉对齐（单文件含全量结构 + 种子，已验证可在空库完整执行且可重复执行），但对**已存在的库**仍无版本化增量手段。
- 建议：引入 Flyway，`V1__init.sql` 打基线，后续变更全走版本化脚本。

### P1-9 上传校验无魔数（Magic Number）
- 证据：`StorageService.java:66-88` 仅信任客户端 `Content-Type` + 扩展名。
- 影响：可伪装上传（当前白名单不含 svg/html，直接 XSS 面小，但可上传伪装图片钓鱼）。
- 建议：读文件头 8 字节比对魔数；上传接口加频控。

### P1-10 token 存 localStorage
- 证据：`request.ts:16`。XSS 一旦发生即可窃取（当前 markdown `html:false` 面小，但第三方依赖劫持不可控）。
- 建议：毕设可保留，论文注明取舍；生产建议 httpOnly Cookie + CSRF 防护。

## 五、已达标项（真实亮点，勿推翻）

1. **SQL 注入面干净**：全部 MyBatis-Plus 参数化（`.like/.last("LIMIT 1")`，无 `${}` 拼接）。
2. **统一异常处理**：`GlobalExceptionHandler` 分类覆盖 6 类异常，对外不泄堆栈，内部 `log.error` 留痕。
3. **Markdown XSS 防护**：`markdown.ts:29` `html:false` + 代码转义 + 外链 `noopener noreferrer`。
4. **上传基础校验**：类型白名单 + 分用途大小上限 + UUID objectKey 防路径穿越 + SVG 排除（`StorageService.java:38-49,122-135`）。
5. **访问埋点已生产化**（10-06 凌晨改造）：有界队列 2000 + 满员丢弃计数 + 单线程异步不阻塞业务 + 分批清理 + 定时任务 90 天保留（`VisitService.java:35-47,87-97`、`application.yml:72-74`、`@EnableScheduling`）。
6. **XFF 可信代理白名单**：仅白名单来源才采信 X-Forwarded-For，防客户端伪造归属地（`application.yml:66-71`、`config/ClientIpConfig`）。
7. **互动幂等**：`uk_user_article`/`uk_user_target` 唯一索引 + DuplicateKeyException 兜底（`init.sql:197,214`）。
8. **浏览量原子去重**：`uk_article_visitor` + INSERT IGNORE 影响行数判定（`init.sql:230`）。
9. **数据库规范**：15 表统一 InnoDB + utf8mb4，关键二级索引齐全（`t_article` idx_status_publish / `t_visit_log` idx_visit_time）。
10. **前端工程**：TS `strict:true`、静态资源 30d immutable、gzip、路由懒加载分包。
11. **依赖注入式密钥**：yml 全部 `${ENV:default}` 形态，机制具备，只差默认值清理。
12. **compose 编排意识**：`restart: unless-stopped`、mysql healthcheck + `depends_on.condition`。
13. **双 Token 会话体系**（10-07 整改）：access 2h / refresh 7d 分离，refresh 带 `jti` 且 `type` claim 防混用；Redis 撤销登记（`blog:auth:refresh:{jti}`，删除即撤销）；刷新**轮换制**且**回库读最新 `role`/`status`**（降权/禁用立即生效）；前端 401 单飞刷新 + 重放，并发 401 不会重复刷新（`request.ts` 模块级 Promise）。
