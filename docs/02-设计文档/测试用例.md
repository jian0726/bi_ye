**全局事实（验收时勿当成缺陷）**：

| 项 | 事实 |
|---|---|
| 鉴权实现 | 项目**未引入 Spring Security**，仅用 `spring-security-crypto` 做 BCrypt；鉴权由 `AuthInterceptor` + `AuthContext` 完成 |
| 越权响应形态 | **HTTP 200 + 业务码**：`code=401`「请先登录」/ `code=403`「无权限访问管理后台」，用例中的 401/403 均指业务码 |
| 登录态 | **双 Token**（access 2h + refresh 7d），有 `POST /auth/refresh`（轮换制）与 `POST /auth/logout`（撤销 refresh）；**无 access 黑名单**——access 到期前仍有效，靠 2h 短效期收敛风险 |
| 密码规则 | 注册 / 改密 / 重置统一 **6–32 位**，不强制字母+数字（纯数字 6 位即可注册） |
| Redis 用途 | **两类**：①找回密码验证码（`blog:verify:*`）；②refresh token 撤销登记（`blog:auth:refresh:{jti}`，删除即撤销）。浏览量、热门榜、限流、access 黑名单均不经 Redis |
| 浏览量口径 | **独立访客去重**：同一访客对同一篇文章终身只计一次；访客标识 = 登录用户 `u:{userId}`，游客 `ip:{客户端IP}`；去重由 `t_view_record.uk_article_visitor` 唯一索引承担，不经 Redis |
| 分类 | 只有 3 个（记录 1 / 游记 2 / 随笔 3），**无「技术」分类** |
| IP 归属地 | **不走任何第三方接口**：xdb 数据文件随包内置、启动时载入内存（启动日志可见 `ip2region xdb 载入成功: ip2region/ip2region_v4.xdb (11122036 bytes)`）。离线环境下功能完全正常；仅 IPv6 地址因未引入 v6 数据文件返回「未知」 |

## 十五、会话与令牌（TC-N）

规则：access 2h / refresh 7d；两者带 `type` claim **不可混用**；refresh 采用**轮换制**（用一次即换新，旧的立即作废）；撤销状态存 Redis（`blog:auth:refresh:{jti}`），删除即撤销。

| 编号 | 类型 | 前置 | 操作与输入 | 预期结果 |
|---|---|---|---|---|
| N01 | 正常 | 已注册 | 登录成功 | 响应含 `token`（access）与 `refreshToken` 两个字段，均已写入前端 `localStorage` |
| N02 | 正常 | 持有有效 refresh | `POST /auth/refresh` 提交 refresh | 返回**新的一对** access + refresh；旧 refresh 立即失效 |
| N03 | 异常 | 已用过一次 refresh | 拿**旧 refresh** 再次调 `/auth/refresh` | 拒绝并 401（jti 已被撤销） |
| N04 | 正常 | 刚刷新过 | 用**新 refresh** 再调 `/auth/refresh` | 成功，再次换发新对（连续轮换不中断） |
| N05 | 异常 | — | 拿 **refresh token** 当 Authorization 访问 `GET /auth/me` | 401（`parseAccess` 校验 `type=access` 不通过） |
| N06 | 异常 | — | 拿 **access token** 提交给 `POST /auth/refresh` | 拒绝（`parseRefresh` 校验 `type=refresh` 不通过） |
| N07 | 正常 | 已登录 | `POST /auth/logout` 提交 refresh | 该 refresh 的 jti 从 Redis 删除；再用它刷新返回 401 |
| N08 | 异常 | 管理员已被降为普通用户 | 用其**旧 refresh** 调 `/auth/refresh` | 换发的新 access 中 `role` 为**普通用户**（角色回库读取，非沿用旧 token 声明）；随后访问 `/api/admin/**` 返回 403 |
| N09 | 异常 | 账号已被管理员禁用 | 该账号的 refresh 调 `/auth/refresh` | 拒绝并返回 403「账号已被禁用」，同时撤销其 refresh 登记 |
| N10 | 边界 | 已登录 | access 过期后访问受保护接口 | 前端拦截 401 → 静默调 `/auth/refresh` → **重放原请求**，用户无感知（不跳登录页） |
| N11 | 边界 | 已登出（本地无 refresh） | access 过期后访问受保护接口 | 直接清本地登录态并跳登录页（不重复请求刷新） |

> **说明**：未做 access token 黑名单——access 到期前始终有效，靠 2 小时短效期收敛风险。这是"不引入 Redis 存 access 撤销名单"的取舍，与「Redis 只承担天然带有效期的数据」原则一致。
