## 二、业务流程设计

### 2.1 用户注册流程（手机号 / 邮箱，至少填一项）

```mermaid
flowchart TD
    S(["开始"]) --> A["打开注册页"]
    A --> B["填写：手机号或邮箱（至少一项）+ 昵称 + 密码"]
    B --> C{"前端格式校验"}
    C -->|格式错误| C1["实时提示格式不正确"] --> B
    C -->|通过| D["提交注册请求"]
    D --> E{"至少填写一项？"}
    E -->|否| E1["400 请填写手机号或邮箱"] --> B
    E -->|是| F{"手机号已被注册？"}
    F -->|是| F1["400 该手机号已被注册"] --> B
    F -->|否| G{"邮箱已被注册？"}
    G -->|是| G1["400 该邮箱已被注册"] --> B
    G -->|否| H["BCrypt 加密密码"]
    H --> I["写入 t_user<br/>role=USER, status=1"]
    I --> J["签发 JWT<br/>subject=userId, claim=role"]
    J --> K["返回 token + 用户信息"]
    K --> L(["自动登录并进入首页"])
```

### 2.2 用户登录流程

```mermaid
flowchart TD
    S(["开始"]) --> A["打开登录页"]
    A --> B["输入账号（手机号 / 邮箱任一）+ 密码"]
    B --> C["提交登录请求"]
    C --> D["按 phone OR email 匹配 t_user<br/>LIMIT 1"]
    D --> E{"账号存在且密码匹配？"}
    E -->|否| F["400 手机号/邮箱或密码错误<br/>（不区分账号是否存在）"] --> B
    E -->|是| G{"status == 0 ？"}
    G -->|是| H["403 账号已被禁用"] --> B
    G -->|否| I["签发 JWT<br/>subject=userId, claim=role"]
    I --> J{"role == ADMIN ？"}
    J -->|是| K["写入本地用户态<br/>可进入管理后台"]
    J -->|否| L["写入本地用户态<br/>进入博客前台"]
    K --> M{"URL 带 redirect ？"}
    L --> M
    M -->|是| N["跳回触发登录的原页面"] --> O(["结束"])
    M -->|否| P["跳转首页"] --> O
```

### 2.3 博客前台访问流程

```mermaid
flowchart TD

    A --> B{"本地是否已登录"}
    B -->|是| C["请求头携带 Bearer Token"]
    B -->|否| D["以游客身份访问"]
    C --> E["AuthInterceptor 解析 Token<br/>写入 AuthContext"]
    D --> F["AuthInterceptor 放行<br/>上下文为空"]
    E --> G["展示首页：刊头 + 最近写的 + 时间轴"]

    H --> I{"用户操作"}
    I -->|点击文章| J["进入详情页"]
    I -->|选择分类| K["按 categoryId 筛选<br/>游记 / 随笔 / 记录各用独立版式"]

```

### 2.4 文章发布流程（草稿 / 发布 / 隐藏）

```mermaid
flowchart TD
    S(["管理员登录"]) --> A["进入文章管理"]
    A --> B["点击新增文章"]
    B --> C["填写标题、摘要"]
    C --> D["Markdown 编辑器撰写正文（实时预览）"]
    D --> E["选择分类、标签、封面"]
    E --> G{"选择保存方式"}
    G -->|保存草稿| H1["status = 0"]
    G -->|直接发布| H2["status = 1，publish_time = now"]
    H1 --> I["统计：word_count = 去空白字符数<br/>read_minutes = max(1, ⌈字数/400⌉)"]
    H2 --> I
    I --> J["写入 t_article（作者取当前登录管理员）"]
    J --> K["重建 t_article_tag 关联（先清后插）"]
    K --> L{"是否发布？"}
    L -->|是| M["前台列表可见"]
    L -->|否| N["仅后台可见，前台不返回"]
    M --> O(["结束"])
    N --> O
    G -->|后续改状态| P["PUT /admin/articles/{id}/status<br/>草稿 ⇄ 已发布 ⇄ 隐藏"]
    P --> O
```

### 2.5 点赞 / 收藏流程（账号维度）

```mermaid
flowchart TD
    S(["点击 ❤ 或 🔖"]) --> A{"已登录？"}
    A -->|否| A1["跳转登录页<br/>?redirect=当前文章"] --> Z(["结束"])
    A -->|是| B["取 AuthContext.getUserId()"]
    B --> C{"userId 为空？"}
    C -->|是| C1["401 请先登录"] --> Z
    C -->|否| D["插入 t_like_record / t_collect<br/>（user_id, target_id）"]
    D --> E{"唯一索引冲突？"}
    E -->|是| E1["DuplicateKeyException<br/>→ 400 已经点过赞啦 / 已收藏"] --> Z
    E -->|否| F["UPDATE 目标表计数 +1<br/>（article.like_count / collect_count）"]
    F --> G["返回成功，前台红心置为实心"]
    G --> H["刷新页面"]
    H --> I["列表 / 详情按 user_id 批量查记录"]
    I --> J["liked / collected 回显为 true"]
    J --> K["红心保持实心，计数与库一致"]
    K --> Z
    L(["取消点赞 / 取消收藏"]) --> M["删除记录"]
    M --> N["计数 -1（GREATEST 兜底不小于 0）"]
    N --> Z
```

**设计要点**：去重由数据库唯一索引承担，不依赖 Redis 或内存；"是否点过赞"由记录表回显，因此刷新、换设备、换会话都能正确恢复——这是修复"刷新后红心消失"问题后的最终方案（详见数据库设计文档 3.6）。

### 2.6 留言板（文字雨）流程

```mermaid
flowchart TD
    S(["进入留言页"]) --> A["GET /portal/messages<br/>拉取历史留言（page=1&size=50）"]
    A --> B["为每条留言随机分配<br/>横向位置 / 落速 / 出现延迟"]
    B --> C["canvas 逐帧绘制整句字幅<br/>缓缓下落，出生淡入、近底部淡出"]
    C --> C2["鼠标左右移动 → 全局风向偏移<br/>带惯性与微倾"]
    C2 --> D{"用户提交留言"}
    D --> E{"已登录？"}
    E -->|是| F["POST /portal/messages 落库"]
    F --> G["重新拉取列表"]
    G --> H["新字幅加入飘落队列"]
    E -->|否| I["仅本地飘落这一次<br/>不落库，刷新即散"]
    I --> Z(["结束"])
    H --> Z
    J(["博主进入后台留言管理"]) --> K["GET /admin/messages<br/>按 IP 属地筛选、按时间倒序分页"]
    K --> L["DELETE /admin/messages/{id}<br/>删除违规留言，前台字幅一并消失"]
    L --> Z
```

**设计要点**：整句字幅在 canvas 上统一绘制，而非为每句留言生成独立 DOM 节点——留言数量增长时只增加绘制指令，不增加布局与合成开销；飘出视野的字幅从另一侧回收复用，避免对象无限增长。

### 2.8 后台权限校验流程

```mermaid
flowchart TD
    S(["请求 /api/admin/**"]) --> A["AuthInterceptor.preHandle"]
    A --> B{"OPTIONS 预检？"}
    B -->|是| B1["直接放行"] --> Z(["结束"])
    B -->|否| C["截取 context-path<br/>得到业务路径"]
    C --> D["读取 Authorization 头<br/>去掉 Bearer 前缀"]
    D --> E{"Token 可解析且未过期？"}
    E -->|是| F["写入 AuthContext.LoginUser<br/>userId + role"]
    E -->|否| G["claims = null"]
    F --> H{"是 /admin 路径？"}
    G --> H
    H -->|否| I["门户区直接放行<br/>上下文有则用，无则视为游客"] --> Z
    H -->|是| J{"claims 为空？"}
    J -->|是| J1["返回 401 请先登录"] --> Z
    J -->|否| K{"AuthContext.isAdmin() ？"}
    K -->|否| K1["返回 403 无权限访问管理后台"] --> Z
    K -->|是| L["放行至 Controller"] --> Z
    M["请求结束 afterCompletion"] --> N["AuthContext.clear()<br/>防止线程复用串号"]
```

**实现说明**：鉴权由 Spring MVC 拦截器（`AuthInterceptor`）统一完成，而非 Spring Security 过滤器链；错误响应采用 **HTTP 200 + 业务码**（`code` 401 / 403），前端统一按 `code` 判断并处理。

## 四、状态机设计

### 4.1 文章状态流转

```mermaid
stateDiagram-v2
    [*] --> 草稿 : 新建并保存草稿（status=0）
    [*] --> 已发布 : 直接发布（status=1）
    草稿 --> 已发布 : 点击发布
    已发布 --> 草稿 : 撤回为草稿
    已发布 --> 隐藏 : 设为隐藏
    隐藏 --> 已发布 : 重新发布
    草稿 --> [*] : 删除（物理删除，级联清理点赞/收藏）
    已发布 --> [*] : 删除（物理删除，级联清理点赞/收藏）
    隐藏 --> [*] : 删除（物理删除，级联清理点赞/收藏）
```

> `定时待发布` 状态与相应流转为后续版本预留（见 2.9），本期不启用。

### 4.2 用户状态流转

```mermaid
stateDiagram-v2
    [*] --> 正常 : 注册成功（status=1）
    正常 --> 禁用 : 管理员禁用（status=0，不可登录）
    禁用 --> 正常 : 管理员启用
    正常 --> [*] : 不存在删除入口（保留互动记录完整性）
```

### 4.3 点赞记录流转（按账号）

```mermaid
stateDiagram-v2
    [*] --> 未点赞 : 用户访问文章
    未点赞 --> 已点赞 : 点击点赞，插入 t_like_record，计数 +1
    已点赞 --> 已点赞 : 重复点击被唯一索引拦截（400 已经点过赞啦）
    已点赞 --> 未点赞 : 取消点赞，删除记录，计数 -1
    已点赞 --> [*] : 目标被删除时级联清理记录
    未点赞 --> [*] : 目标被删除
```
